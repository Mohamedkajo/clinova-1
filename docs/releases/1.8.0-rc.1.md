# Clinova 1.8.0-rc.1

Release type: controlled Release Candidate

## Release scope

- PostgreSQL-only production startup with strict, secret-safe environment validation.
- Separate PM2 web, background worker, and backup scheduler processes with graceful readiness and restart behavior.
- Pre-deployment PostgreSQL and upload backups, isolated PostgreSQL restore verification, and documented retention/rollback controls.
- Safe operational readiness for database state, migration version, worker heartbeat, failed jobs, queue backlog, storage availability, and persistent logs.
- HTTPS reverse-proxy guidance, trusted-proxy enforcement, origin restrictions, a self-only script CSP, security headers, request/upload limits, and production demo-data guards.
- Hotfix 2.7.1 adds the one-time `npm run production:init` CLI for transactionally creating the first Platform Owner and provisioning the first clinic on an empty migrated PostgreSQL installation. It does not weaken the runtime owner gate or add an HTTP bootstrap endpoint.

No new business module or external messaging provider is included. Reminder dispatch remains an internal simulation.

First-install order: `npm ci`, `npm run release:validate`, `npm run db:migrate`, `npm run production:init`, `npm run db:verify`, then `npm run start:production`. Initialization credentials must be injected only for that command and removed afterward.

## Deployment gate

The candidate may be promoted only after the complete SQLite regression suite, PostgreSQL workflow suite, migration and restore tests, process restart check, role/tenant/file/finance security checks, and browser console review pass. Use the [Sprint 2.7 production runbook](../production/SPRINT-2.7-RELEASE-CANDIDATE.md).
