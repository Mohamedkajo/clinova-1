# Clinova 1.8.0-alpha.1

Release type: client-demo Alpha
Sprint: 1.5 — Alpha 0.1 Quality, Demo Polish, and Release Readiness

## Highlights

- Polished the existing login-to-patient-to-booking-to-calendar-to-queue workflow without adding business modules.
- Added consistent Arabic, Hebrew, and English appointment copy.
- Improved patient and booking form labels, required indicators, inline errors, saving states, success feedback, and duplicate-submit prevention.
- Added keyboard focus entry, focus trapping, Escape handling, and focus restoration for booking, patient profile, patient form, and appointment detail dialogs.
- Removed an avoidable full bootstrap refresh after patient creation.
- Removed an avoidable booking-dialog rerender when service duration changes.
- Reused the shared appointment workspace refresh for calendar and queue updates.
- Fixed the post-login calendar loading state and reset role-scoped workspace data when users sign out.
- Added a safe, repeatable, fictional demo database with four documented roles.

## Reliability and security

- Existing signed sessions, protected routes, RBAC, tenant isolation, XSS escaping, conflict detection, appointment status authorization, and audit behavior remain in place.
- Demo tooling refuses production, PostgreSQL, weak demo passwords, and paths outside `.demo/`.
- Demo mode disables outbound WhatsApp and automatic backups.

## Demo instructions

See [Alpha demo instructions](../deployment/ALPHA_DEMO.md).

## Known limitations

- Alpha 0.1 is intended for controlled client demonstrations, not production deployment.
- Demo data is local to one SQLite database and is reset as a complete dataset; it is not a multi-user demo provisioning service.
- English coverage is complete for the reviewed core workflow, while older secondary modules may still contain Arabic/Hebrew-first copy.
- No recurring appointments are supported.
- WhatsApp delivery remains disabled in the demo environment.
- Platform billing and production provisioning still require their existing external operational setup.
- Automated accessibility checks are limited to regression assertions and manual keyboard review; no formal WCAG certification is claimed.

## Startup

For a normal local database, run `npm run init-db` before `npm start`. For the isolated demo, use `npm run demo:seed`, `npm run demo:start`, and `npm run demo:reset` as documented.
